# Peri audit — November 2026

Scope: every non-test source file under `src/` at `main` (`111ae19`), ~19.8k lines.
Baseline: `cargo test` 274 passed / 10 ignored; `cargo clippy --all-targets` clean.

Severity: **High** = user-visible misbehaviour in normal use; **Medium** = wrong in a reachable
edge case or a clear slowdown on large libraries; **Low** = polish, docs, hygiene.

## Bugs

### B1 — Play does nothing after the queue runs out (High)
`App::finish` (`src/app.rs`) calls `Engine::stop`, which drops the `Player`. Afterwards
`Engine::finished()` is `player.is_some_and(empty)` → `false`, so `App::toggle` skips its
"finished queue: reload the track" branch, flips `playing` to true and calls `engine.play()` on
no player. The button shows Pause, nothing sounds, the seek bar never moves.
Headless tests use `Output::Silent`, so they never see it.
**Fix:** decide restart by app state, not engine state (e.g. `!self.playing && no player loaded`),
or keep a flag set by `finish`. Add an `Engine::is_loaded`.

### B2 — Adding a folder while a scan runs drops the first scan (High)
`start_scan` replaces `self.scan`; dropping the old receiver stops the launch scan. If the user
adds a folder before the launch scan finishes, the append-scan result is merged into the *old*
(possibly empty) library — the saved roots and the library diverge until the next launch.
**Fix:** when a scan is running, rescan all saved roots (non-append) instead of appending, or
queue the roots onto the running scan.

### B3 — A rescan replaces the play queue with the library view (Medium)
`set_library` rebuilds `queue` from `filtered_or(i)` with `self.shuffle`, discarding a queue
started from an album, artist, label, search or Home list, and its shuffle order.
**Fix:** remap the existing queue's indices by path into the new `tracks`, dropping missing ones.

### B4 — "Open containing folder" fails for paths with `#`, `%`, `?`, spaces (Medium, Linux)
`reveal` builds `file://{path}` without percent-encoding, so D-Bus `ShowItems` gets an invalid
URI and falls back to `xdg-open` of the parent (or fails).
**Fix:** percent-encode each path byte outside the unreserved set + `/`.

### B5 — `Queue::new` panics if the started track isn't in its list (Medium)
`.expect("the started track is in its list")`. All callers currently guarantee it, but
`play_album(a, Some(from))` with a `from` not in `filtered` (album outside the view list but
`shown_albums` stale after a rescan) can reach it. A panic kills the player.
**Fix:** return `Option<Queue>` / fall back to inserting `start`; no panic in UI paths.

### B6 — Cover LRU smaller than a screenful thrashes (Medium)
`covers::CAPACITY = 160`. Small cards on a large/zoomed-out window can show >160 covers; each
arrival evicts a visible one, which is re-requested on the next build → endless decode loop.
`Inner::touch` is also O(n) (`VecDeque::position`).
**Fix:** never evict covers touched in the current frame (generation stamp), and make touch O(1)
(e.g. stamp-based LRU in the `HashMap`).

### B7 — Volume knob drag keeps unmuting (Low)
`set_volume` always clears `muted`; the pointer-lock handler and Escape-cancel both call it, so
cancelling a drag while muted unmutes. Minor; document or preserve `muted` on cancel.

## Performance

### P1 — Page models recomputed on every frame (High for big libraries)
`view/search.rs`, `view/artists.rs`, `view/collab.rs`, `view/labels.rs` and `view/home.rs` call
`search()`, `artist::page()`/`involved()`, `collab::page()`, `label::page()`,
`recently_added/played()` inside the view function. The view runs on every poll that changes
anything — at least every 200 ms tick while playing (position updates) — so a whole-library
scan happens 5×/s just to move the seek bar.
**Fix:** cache each page model in `App` keyed by (page, query, library version, relations
version, with_aliases); invalidate in `set_library`, `edit_relations`, `record_play`, etc.

### P2 — Quadratic loops inside the page builders (High)
- `search::search` `listed` closure: `top.albums.iter().chain(&found).any(|a| albums[a].tracks.contains(i))` per track → O(tracks × albums × album size).
- `artist::page`: `appears_on` / `on_own` do `own.iter().any(|a| albums[a].tracks.contains(i))` per track.
- `collab::page`: same pattern.
- `App::album_of` is a linear scan over all albums; called per visible row by `song_cover`, `album_link`, the player bar, etc.
**Fix:** build a `track → album` index (`Vec<usize>`) alongside `albums` in `set_library`/`record_play`; use `HashSet`s for membership.

### P3 — Empty search query does per-track allocations (Medium)
`refilter`/`view_songs` call `evaluate(view, records, "")`; `Track::matches("")` still formats and
lowercases title/artist/album for every track. Short-circuit when the query is blank.

### P4 — Appending a scan is O(n·m) (Medium)
`set_library(append)`: `all.retain(|t| !tracks.iter().any(|n| n.path == t.path))`. Use a
`HashSet<&Path>`. Also the merged list is sorted twice (`library::sort` before and after `resolve`).

### P5 — Blocking file I/O on the UI thread (Medium)
- `App::load` → `library::read_cover` re-probes the whole file (with cover art) synchronously.
- `Engine::load` opens and probes the decoder synchronously (unavoidable-ish; note only).
- `show_details` → `details::read` parses the file twice (Probe + format-specific read).
**Fix:** move the now-playing cover onto the existing `Covers` workers (it already caches by song path).

### P6 — Every keystroke in a filter value rewrites `prefs.json` (Low)
`value_input.on_change` → `views_changed` → `store.save`. Debounce saving (save on blur/close or
after idle), keep `refilter` immediate.

### P7 — `poll_plays` rebuilds all albums on a counted play (Low)
`album::build` + `refilter` for one play count. Acceptable (once per song) but could update the
one album in place.

## Docs / hygiene (Low)
- D1: README says Home shows "10 newest albums… 10 songs"; `RECENT_COUNT = 20`.
- D2: README links Rune at `github.com/anomalyco/rune`; `Cargo.toml` uses `github.com/Narwhai/rune`.
- D3: `app.rs` has stray/duplicated doc comments: "Plays song `i` of `list`…" above `show_details`;
  "`AppSpec::poll`…" above `reveal`; "A song row's key…" above an `impl App` block;
  `setup` has two summary lines. `queue.rs` has a double blank line.
- D4: `Rng::below` / `shuffle` use `%` (modulo bias; negligible for shuffle sizes). Note only.

## Not issues (checked)
- MD5 implementation matches RFC 1321 vectors; Last.fm signing excludes `format` correctly.
- Scan doesn't follow symlinked dirs (`file_type` is not followed) — no loops.
- Graph layout cache writes atomically (tmp + rename); worker cancels on drop.
- `plays.jsonl` appends one `write_all` per line; torn lines are skipped on load.
